# Socratic Task Interviewer

## Purpose
Stop premature output on complex tasks. Gather the information needed to do the job well, align on a plan, and only then execute — so the deliverable is right the first time.

## When to use it
Especially for:
- Building CRM features
- Creating new outreach systems
- Writing proposals
- Creating package/pricing strategy
- Building lead research workflows
- Creating automated follow-up workflows
- Defining partner/referral terms

(Skip for small, well-specified one-offs.)

## What it should ask me for
5–10 specific questions tailored to the task — not generic. Examples by task type below.

## What files/context it should read first
1. `ABOUT ME/about-me.md` (incl. decisions already made — don't re-ask those).
2. `ABOUT ME/voice-profile.md`, `ABOUT ME/anti-ai-writing-style.md`.
3. Relevant `PROJECTS/hotel-outreach-crm/` files.

## Exact instructions for the Skill
1. Read the context files first so questions don't re-ask settled decisions.
2. Do **not** produce the final deliverable yet.
3. Ask **5–10 specific questions** needed to do the task well.
4. Wait for answers.
5. **Summarize the answers** back concisely.
6. **Propose a plan** (steps + what will be produced).
7. Only after Devon approves, create the final deliverable (handing to the right Skill if applicable).

### Example question sets
- **Pricing strategy:** target margin? floor price? what does a hire cost in their market? per-property vs flat? discount for 6-month? what's the anchor comparison?
- **Follow-up workflow:** how many touches max? channels? timing gaps? auto-update CRM? which objections to automate?
- **CRM feature:** which fields change? who reads the output? manual or automated entry? what breaks today?

## Output format
```
INTERVIEW — [task]
Questions:
1. … (5–10, specific)
[after answers]
Summary of your answers: [recap]
Proposed plan: [numbered steps + deliverable]
Awaiting approval to proceed.
```

## Quality rules
- Questions must be specific to the task, never generic filler.
- Never re-ask decisions already settled in `about-me.md`.
- Plan must be concrete and approval-gated.

## What it must never do
- Never produce the final deliverable before questions + plan approval.
- Never ask vague questions ("what do you want?").
- Never exceed 10 questions or drop below 5 for a major task.

## Usage example
> **Devon:** Build me a pricing strategy for the retainer packages.
>
> **Skill:** [reads context → asks 8 specific pricing questions → summarizes answers → proposes a tiered structure plan → waits for approval before writing it into `package-pricing-notes.md`.]
