# Proposal and Package Generator

## Purpose
Turn interest into a clean, simple proposal built around the right package — always framed by cost savings vs. an in-house hire.

## When to use it
- A lead is past the trial or has asked about pricing / what an engagement looks like.
- Devon needs a proposal he can send or adapt quickly.

## What it should ask me for
1. Lead name, property type, and number of properties.
2. Which package(s) fit, or let the Skill recommend.
3. Real price numbers if Devon has them (otherwise placeholders).
4. Desired monthly output level.

## What files/context it should read first
0. **Read these three first, every time:** `ABOUT ME/about-me.md` (identity + settled decisions), `ABOUT ME/voice-profile.md` (how Devon sounds), `ABOUT ME/anti-ai-writing-style.md` (banned/avoid list).
1. `ABOUT ME/Brand Context/ARCHER-DESIGN-BRAND-CONTEXT.md` — offers, positioning, proof, tone.
2. `Examples/Portfolio Proof/PORTFOLIO-PROOF.md` — proof to embed.
3. `crm/CRM-SCHEMA.md` — to log the proposal stage.

## Exact instructions for the Skill
1. Read the Brand Context File.
2. Recommend the best-fit package(s) for the lead's property type and scale.
3. Build each selected package with the full structure below.
4. Frame everything as cost savings + creative bandwidth vs. hiring in-house. Quantify the savings angle wherever possible (a hire = salary + benefits + recruiting + management).
5. Use **placeholder** price ranges clearly marked `[confirm]` unless Devon gave real numbers.
6. Write a short, human proposal message to accompany it.

### Packages
- **1-Month Paid Pilot** — single billed month to prove ongoing fit.
- **6-Month Retainer** — core engagement, consistent monthly output, best value.
- **Multi-Property Pilot** — test across 2–3 properties for groups.
- **Restaurant / F&B Package** — menu, specials, seasonal cadence.
- **Event / Wedding Package** — promo creative to drive bookings.
- **Spa / Wellness Package** — premium, calm content cadence.
- **Select-Service Hotel Package** — right-sized output for limited-service.

## Output format
For each package:
```
PACKAGE — [name]
Positioning: [1–2 sentences]
Deliverables: [what they get]
Timeline: [cadence]
Client responsibilities: [what they provide]
Approval workflow: [feedback rounds → delivery]
Monthly output: [# pieces / types]
Cost-savings framing: [vs. in-house hire, quantified where possible]
Recommended price range: [$ placeholder — confirm]
Terms to clarify: [usage rights, revisions, asset access, contract length]
Short proposal message: [text]
```

## Quality rules
- Always lead positioning with cost savings / bandwidth, not features.
- Pricing is clearly placeholder until Devon confirms.
- Deliverables and monthly output must be concrete numbers, not "lots of content."
- The proposal message stays short and human — the proposal does the detail work.

## What it must never do
- Never present invented prices as final.
- Never over-promise output volume.
- Never bloat the proposal into a 5-page agency deck — keep it simple.
- Never use banned phrases.

## Usage example
> **Devon:** Lead's a 3-property select-service group, interested after the trial. Proposal?
>
> **Skill:** [recommends Multi-Property Pilot → 6-Month Retainer; builds both with concrete monthly output per property, cost-savings framing vs. one shared in-house designer's salary, placeholder pricing, short proposal message.]
